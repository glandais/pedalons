## Reste à faire

`WEB-193` **Invitation sans compte : l'activation ramène à l'accueil, pas à l'invitation** — une
personne invitée qui n'a pas de compte ouvre `/invitation?token=…`, part créer son compte
(`LoginForm`), clique le lien de vérification reçu par e-mail, choisit un mot de passe, se voit
proposer une passkey, puis arrive sur l'accueil : `VerifyEmailPage.tsx` finit par
`navigate(paths.home())`, sans regarder s'il y a une invitation. Le jeton gardé par
`AcceptInvitationPage.tsx` (`pendingInvitationToken`, en `sessionStorage`) ne sert pas : le lien de
vérification s'ouvre dans un autre onglet, parfois un autre navigateur, où ce stockage est vide. Le
seul rattrapage est `PendingInvitationsBanner`, affiché sur la liste des équipes seulement
(`TeamListPage.tsx`) — l'accueil dit « Vous n'êtes membre d'aucune équipe » à quelqu'un qui vient
d'être invité.

À faire :

- après l'activation (et après la passkey, proposée ou refusée), si le compte a une invitation en
  attente, mener à elle plutôt qu'à l'accueil. La source fiable est le serveur
  (`useListMyInvitations`, résolu par l'adresse e-mail), pas le `sessionStorage` ;
- une fois l'invitation acceptée, arriver sur la page de l'équipe (c'est déjà ce que fait
  `AcceptInvitationPage` pour une personne connectée) ;
- montrer les invitations en attente sur l'accueil aussi, pas seulement sur la liste des équipes
  (se recoupe avec `WEB-194`, qui refait l'état « aucune équipe »).

À couvrir par un e2e Playwright : invitation → création de compte → vérification dans un contexte
neuf → arrivée dans l'équipe.
