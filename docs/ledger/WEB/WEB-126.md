## Livré

`WEB-126` **Un parcours importé prend le nom inscrit dans son GPX, et se télécharge sous son propre nom** (31 octobre 2026, contrat inchangé). À l'upload (formulaire « Créer un nouveau parcours » et bouton « Importer GPX »), le navigateur lit le fichier (`frontend/src/lib/gpxNames.ts`) : le nom vient de `<metadata><name>` (ou `<gpx><name>` en GPX 1.0), sinon de la première trace non vide — `<trk>` comme `<rte>`, dans l'ordre du fichier, comme le parseur du serveur —, sinon du nom de fichier ; c'est la règle de l'import du planner (`GpxProcessingService.documentName`). Le formulaire propose sous le champ « Noms trouvés : » chaque nom de trace et le nom de fichier, et un fichier suivant ne remplace que le nom qu'un fichier précédent avait rempli. Au téléchargement, les fichiers d'un parcours ne s'appellent plus `original.gpx` / `filtered.gpx` / `route.fit` jusqu'à sa première modification : `GpxProcessingService.routeFileName` leur donne le slug à chaque écriture (création, remplacement du tracé, rattrapage HD, réécriture des points de passage) ; un ancien lien marche toujours, le téléchargement retrouve l'asset par son id. Le `<name>` du GPX et le nom du FIT sont celui du parcours, plus celui du fichier importé ni `noname` ; une trace que le fichier nommait garde son nom, une trace sans nom prend celui du parcours (`computeGpx(…, name)`). Les parcours existants gardent le `<name>` de leur fichier d'origine (pas de migration), et renommer un parcours ne réécrit pas ses fichiers. Couvert par `gpxNames.test.ts`, `RouteEditor.test.tsx` (« names read from the GPX file »), `GpxProcessingServiceTest.createTracks_namesTheDownloadedFilesAndTracksAfterTheRoute` et les e2e `flow-routes` (création, import multiple, extension en majuscules) et `flow-rides`. À ne pas défaire : le nom par défaut suit la même règle que le serveur ; un nom tapé à la main n'est jamais écrasé par la lecture du fichier.
