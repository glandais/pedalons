## Livré

`WEB-184` **Le libellé de `USER_TEAM_LIMIT_REACHED` dit ce que fait le serveur** (15 novembre 2026, contrat inchangé) — le site affichait « Vous avez atteint la limite d'équipes rejoignables » (« You have reached the maximum number of teams you can join »), alors que le code n'est levé qu'à la **création** d'une équipe, quand la personne (hors administration de la plateforme) est déjà `ADMIN` d'une équipe non supprimée du domaine (`TeamService.createTeam`) ; être membre d'équipes ne compte pas. `errors.api.USER_TEAM_LIMIT_REACHED` devient « Vous administrez déjà une équipe : il n'est pas possible d'en créer une autre. » / « You already administer a team: you cannot create another one. » (`frontend/src/locales/fr/common.json`, `en/common.json`). Sans nombre : l'erreur ne porte aucun `errorDetails`. Décision D4 du plan [`2026-11-15-gestion-equipe-mobile.md`](../../plans/archive/2026-11-15-gestion-equipe-mobile.md) §5.2 ; la même clé est créée dans l'app par `MOB-165`. Tests : `src/i18n/catalogues.test.ts` (parité des catalogues) ; pas de test du texte lui-même. À revoir avec le plan de monétisation ([`2026-10-17-monetisation.md`](../../plans/2026-10-17-monetisation.md)), qui prévoit une limite par offre : le texte devra alors la nommer.
