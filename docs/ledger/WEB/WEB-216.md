## Livré

Codé le 25 novembre 2026, sans changement de contrat : décision D4 du plan
[`2026-11-25-audit-flux-parcours.md`](../../plans/2026-11-25-audit-flux-parcours.md) (W-N1, W-N2,
W-F9). Vitest vert (`useGpxUpload.test.tsx`), `typecheck` et `i18n:check` aussi ; l'e2e
`flow-routes` (import de trois fichiers) est adapté, non relancé ; rien vu dans un navigateur.

- **La liste des parcours ne s'ouvre à la fin que si la personne est restée** sur la page d'où
  l'import est parti (`window.location.pathname` comparé à celui du départ) : partie remplir une
  sortie pendant l'envoi, elle n'en est plus arrachée. Le bilan s'affiche dans tous les cas.
- **Un import à la fois par équipe** : la progression vit dans le cache de requêtes de la page
  (`['gpx-import', équipe]`, jamais lue du serveur, `CLIENT_ONLY_QUERY`), partagée par toutes les
  instances de `useGpxUpload` (en-tête de la liste, tableau de bord, accueil) : « Importer des
  GPX » est grisé partout pendant l'import, et un second ne démarre pas.
- **Chaque refus avec sa raison** : « 2 parcours importés. Fichier refusé : vide.gpx (Le fichier
  GPX ne contient aucune donnée de tracé) » ; le message de l'API (`errors.api.<code>`), « pas de
  connexion » ou « refusé par le serveur » ; singulier pour un seul fichier ; « Aucun parcours
  importé » quand tout est refusé. Les appels ne déclenchent plus un toast par fichier
  (`skipErrorToast`). Les clés `routes.upload.partialFailure*` sont supprimées.
- **Laissé tel quel** : le revêtement « Route » de chaque parcours importé (W-N12), à compléter
  ensuite dans son formulaire, comme dans l'app.
