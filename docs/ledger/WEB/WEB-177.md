## Livré

`WEB-177` **Fonds « Route » et « Gravel », et un interrupteur « Carte claire » en thème sombre** (13 novembre 2026, contrat 14.9.1, description seule) — le sélecteur listait Vélo, Route et Plan, chacun doublé d'une ligne « (sombre) » ou « (clair) ». Config (`application.properties`) : « Plan » (VersaTiles `colorful`) est retiré ; `cycling-road` s'appelle « Route » et vient en premier (fond par défaut, et repli d'un id disparu), `cycling` s'appelle « Gravel » ; les deux sont servis depuis la version publiée sur npm (`@glandais/cycling-style`, jsDelivr, épinglée sur la majeure `@1`) et non plus depuis GitHub Pages, qui suit `develop`. Web : `mapStyleChoices` et les lignes épinglées disparaissent ; `rendersDark(style, dark, lightInDark)`, `mapStyleStore.lightInDark` (clé `pedalons-map-light-in-dark`), un `Switch` « Carte claire » dans `MapStyleSwitcher`, offert seulement en thème sombre sur un fond qui a une variante sombre (`useMapStyle().canForceLight`). CSP : le sprite `cyclo` de ces styles reste sur GitHub Pages, que `csp.js` ajoute dès qu'un style jsDelivr est servi (`CYCLING_STYLE_SPRITE_ORIGIN`). Tests : `mapStyles.test.ts`, `mapStyleStore.test.ts`, `csp.test.js` ; `stubBasemap` (e2e) intercepte l'URL jsDelivr. À ne pas défaire : le réglage est un booléen à part du fond choisi, commun à tous les fonds — il **remplace** la règle de `WEB-141` (rendu mémorisé en absolu) ; en thème clair la carte est toujours claire ; un `pedalons-map-style` hérité `<id>:light` ou `<id>:dark` se lit comme `<id>`, et `:light` vaut « Carte claire » tant que l'interrupteur n'a pas été touché. Pendant mobile : `MOB-148`. Pas vu dans un navigateur, e2e et `ConfigMapSettingsTest` non relancés.
