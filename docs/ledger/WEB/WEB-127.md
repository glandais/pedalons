## Livré

`WEB-127` **Le mode d'une carte (Pente, Revêtement, Météo) fait l'aller-retour avec son plein écran, sur toutes les cartes** (31 octobre 2026, contrat inchangé). Le plein écran d'un groupe s'ouvrait dans le mode de la page (`WEB-117`), mais le retour retombait sur Pente : `useWindColorMode` tenait le mode dans un `useState`. Le mode vit désormais dans l'URL de la page aussi (`?color=`, le paramètre du plein écran, `mapColorFilters.ts`) — groupe, sortie solo, étape, parcours, aperçu GPX — et le bouton retour de `RouteFullscreenView` le rapporte : `navigate(-1)` si le mode n'a pas changé depuis l'ouverture (l'entrée d'historique le porte déjà), sinon `backTo?color=…` à la place de la carte (l'historique ne se réécrit pas derrière soi). Le plein écran d'un parcours et d'un aperçu GPX passent par `MapColorFullscreenView` et s'ouvrent dans le mode de leur page. Pour que deux `useUrlFilters` cohabitent sur une page (participants du groupe et mode de sa carte), le hook garde les paramètres de l'URL qui ne sont pas les siens, au lieu de réécrire tout le query string. Un mode que la carte ne peut offrir (pas de revêtement, prévision partie) se lit Pente sur la page comme en plein écran. Couvert par `RouteFullscreenView.test.tsx` (« returns the mode switched to here… », « carries the mode on its link… »), `useUrlFilters.test.tsx` (« keeps the query string's other parameters… ») et `GroupRouteMap.test.tsx`. À ne pas défaire : `useUrlFilters` n'efface jamais un paramètre qu'il ne possède pas ; le retour sans changement de mode reste un retour d'historique.
