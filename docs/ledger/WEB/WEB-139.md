## Livré

`WEB-139` **Aperçu de partage (OG/SSR) : la date disparaît dès qu'il y a une description (S)** —
dans `frontend/src/config/routeMeta.ts`, la date mène désormais la description de l'aperçu, que
l'entité ait un texte ou non : « 11 octobre 2026 · On roule tranquille… » pour une sortie,
« départ 10 octobre 2026 · … » pour un voyage, et une étape porte enfin son jour, lu dans **son**
fuseau (`TripStageDto.timezone`), pas celui du voyage ; sans texte ni faits, elle garde « Étape du
voyage … » après la date. Le formatage passe par les formateurs des pages (`formatDate`,
`formatTime`), qui vivent maintenant dans `frontend/src/utils/dateFormatCore.ts`, ré-exportés par
`dateFormat.ts` : l'anglais écrit « October 11, 2026 » comme l'écran, plus « 11 October 2026 »
d'`Intl` en `en-GB`. Un fuseau inconnu du runtime retombe toujours sur Paris sans lever. Pas de
changement de contrat. Couvert par `routeMeta.test.ts` (« the date stays in a preview that has a
text (WEB-139) »).

À ne pas défaire :

- **`routeMeta.ts` n'importe pas `utils/dateFormat`** mais `dateFormatCore` : `dateFormat.ts`
  importe l'instance i18next, qui s'initialise au chargement, et `routes.config.ts` lit
  `routeMeta.ts` — les tests de composants qui attendent les clés brutes (`CreateSplitButton`,
  `RoutePlannerField`) se mettaient à voir les libellés traduits.
- **Aucun titre OG ne porte de date**, délibérément : le titre garde le nom (65 caractères), la
  description porte le jour, et les cartes de partage affichent les deux.
