## Reste à faire

`API-210` **Dépôt des surcouches du générateur : la connexion du verrou meurt quand une passe dure (S)** —
`RouteGeneratorOverlayJob.lockedPass` garde une connexion ouverte et inactive pendant toute la passe pour tenir le
verrou consultatif. Le 17 novembre 2026, une passe de staging restée 1 011 s (un dépôt bloqué 16 minutes, corrigé
depuis dans le moteur, `OPS-61`) a fini par « lock failed » : `pg_advisory_unlock` a échoué sur une connexion morte
(« An I/O error occurred while sending to the backend »), et la passe, pourtant terminée, a été journalisée en
erreur. Sans conséquence ce jour-là (le verrou tombe avec la connexion), mais pendant le reste d'une passe longue
un second backend pourrait prendre le verrou. À faire : savoir ce qui coupe la connexion inactive (pool, pare-feu,
`idle_session_timeout`), puis la garder vivante ou reprendre le verrou par étapes ; ne pas compter en échec une passe
dont seul le déverrouillage a échoué.
