## Livré

`API-197` **Dupliquer un aperçu GPX** (2026-11-13, **contrat `14.12.0`**, mineure, ajout pur ; aucune migration) — `POST /api/gpx-previews/{previewId}/copy`, corps `GpxPreviewCopyRequest { name }` (mêmes règles que `RouteDuplicateRequest`) → `201 GpxPreviewDto`, `@RolesAllowed("user")` : tout compte connecté qui a le lien d'un aperçu le copie ; un anonyme reçoit 401, un identifiant inconnu, malformé ou d'un autre domaine 404. `GpxPreviewService.copy` (`@Logged`, hors transaction comme toute création) **rejoue la création** sur le `original.gpx` de la source : il lit l'état, les revêtements, les points du parcours et le départ dans une transaction courte, télécharge le GPX sans connexion tenue, puis appelle `create` avec `countedSave=false` et les revêtements copiés (`surfacesOverride`, seulement si leur nombre colle à celui des traces recalculées). La copie appartient à l'appelant (il la modifie et la supprime ; rétention de 30 jours à partir de sa création), l'original n'est pas touché. La vitesse moyenne est toujours reprise ; la date de départ seulement si elle est à venir et si l'appelant a moins de `GpxLimits.MAX_UPCOMING_DATED_PREVIEWS` aperçus datés à venir — sinon la copie se fait sans date, jamais en 400. Tests qui couvrent : `GpxPreviewCopyResourceTest` (écrit, non lancé). **À ne pas défaire** : l'état du planificateur n'est recopié que si l'appelant est le **créateur** de la source, que l'état est encore lisible et que le planificateur du domaine est ouvert (`drawn` suit l'état gardé) — il est privé (`getPlannerState` refuse les autres), le copier le révélerait ; **une copie ne compte rien** pour `BILL-10` (ni `requirePersonalRoom`, ni enregistrement personnel, même quota épuisé), même décision que pour les copies de parcours (`API-179`).
