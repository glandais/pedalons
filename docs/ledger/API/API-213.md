## Livré

`API-213` **Une mesure d'activation des nouveaux comptes, en décomptes** — API `16.2.0` :
`GET /api/admin/domains/activation?weeks=` (administration de la plateforme seulement, `@Admin`)
rend, par semaine d'inscription (semaine ISO, lundi, UTC) et par domaine, le nombre de comptes
créés, d'adresses vérifiées, de comptes qui ont rejoint une équipe dans les 7 jours suivant leur
création, et de comptes qui se sont inscrits à une sortie dans les 7 jours. `weeks` vaut 12 par
défaut, borné à [1, 52] ; une semaine est `complete` 14 jours après son lundi, quand son dernier
compte possible a eu ses 7 jours. La requête est une seule agrégation SQL sur ce que la base porte
déjà (`users.created_at`, `user_teams.joined_at`, `ride_participations.registered_at` —
`ActivationStatsRepository`), sans index ni colonne de plus.

Le tableau de bord de l'administration (`AdminDashboardPage.tsx`, `ActivationTable.tsx`) montre les
douze dernières semaines et calcule les parts sur les comptes créés ; la lecture est prefetchée
avec les mêmes paramètres (`ACTIVATION_PARAMS`, `adminDashboardData.ts`). L'app n'a rien : c'est
une page d'administration du site.

Décisions à garder : **des décomptes seulement** — aucune ligne ne nomme qui que ce soit, aucun
traceur ni SDK, aucune donnée nouvelle collectée ; il n'y a pas de valeur de référence à viser,
seule l'évolution compte (avant et après `WEB-193`, `MOB-179`, `WEB-194`, `WEB-195`). Biais connus
et acceptés : les comptes supprimés sortent du décompte ; une équipe quittée ou une sortie dont la
personne s'est désinscrite depuis ne comptent plus (les lignes sont effacées) ; créer sa propre
équipe compte comme en rejoindre une ; la migration biketeam n'importe aucun compte, elle ne
fausse donc aucune semaine.

quatre décomptes et la borne des 7 jours, la semaine complète, aucun nom dans la réponse, refus
hors administration) et `frontend/src/components/admin/ActivationTable.test.tsx`.
