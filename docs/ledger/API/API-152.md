## Livré

`API-152` **D+ du service écrit dans le `Path` par une API publique de vcyclist (XS)**
(17 novembre 2026, contrat d'API inchangé, vcyclist `6.15.0`) — `RouteDetailsTrack` posait le D+
et le D- d'osm-route-details avec les setters Kotlin `internal` de vcyclist, appelés depuis Java
sous leur nom généré (`setElevationGainFiltered$io_github_glandais_gpx`) : une montée de version
de vcyclist pouvait le casser à la compilation. vcyclist 6.15.0 expose
`Path.reportElevation(gainM, lossM)`, publique, qui refuse une valeur non finie, un D+ négatif ou
un D- positif ; son nom Java non mangé est garanti côté vcyclist par
`ElevationGainJavaTest.anExternalFigureIsReportedUnderAnUnmangledName`. Le helper unique
`RouteDetailsTrack.reportAscent` (ledger `API-150`) l'appelle désormais ; couvert par
`RouteDetailsTrackTest` et `GpxPipelineTest`.

À ne pas défaire : l'appel reste **après** le dernier `computeDerivedData` du chemin (donc après
`PathJvm.fromCoordinates`), qui remet ces valeurs à NaN ; et le D+ du service **remplace**
l'accumulateur `ElevationGain` de vcyclist, il ne s'y ajoute pas.
