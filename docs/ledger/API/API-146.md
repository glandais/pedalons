## Livré

`API-146` **Une adresse e-mail saisie avec d'autres majuscules retrouve son compte** (27 octobre 2026, contrat d'API inchangé) — signalé depuis l'app iOS : « Mot de passe oublié » n'envoyait aucun e-mail. Le compte avait été créé avec une majuscule en tête d'adresse (clavier iPhone) ; toutes les recherches de compte et de jeton (`UserRepository.findByEmailAndDomain`, `AuthTokenRepository`) comparent l'adresse telle quelle, et la réponse, identique pour une adresse inconnue, ne disait rien. Le même défaut touchait login par mot de passe, code par e-mail et passkey. Désormais `EmailAddresses.normalize` (`strip` + `toLowerCase(Locale.ROOT)`) s'applique dans le constructeur de chaque DTO de requête qui porte une adresse (`RegisterRequest`, `LoginRequest`, `OtpRequest`, `VerifyOtpRequest`, `ForgotPasswordRequest`, `PasskeyAuthenticationRequest`, `EmailChangeRequest`) ; les invitations normalisaient déjà (`TeamInvitationService.normalize`). `V80__lowercase_emails.sql` passe en minuscules les adresses de `users` (sauf collision avec une adresse déjà prise sur le domaine : aucune au 27 octobre 2026) et d'`auth_tokens` ; le seul compte concerné en prod avait été corrigé à la main le même jour. Couvert par `AuthResourceTest` (`forgotPassword_ignoresTheCaseOfTheAddress`, `login_ignoresTheCaseOfTheAddress`, `register_storesTheAddressInLowerCase`). À ne pas défaire : l'adresse est normalisée à l'entrée, dans le DTO, et stockée en minuscules — toute nouvelle requête portant une adresse doit passer par `EmailAddresses.normalize`.
