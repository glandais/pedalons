## Livré

`API-206` **Générateur de parcours sur un graphe OSM : les lots 0 à 3 d'`API-207`** (16 novembre 2026, **contrat `15.0.0`**, majeure : le curseur remplace la fréquentation) — le moteur vit dans osm-route-details (api 1.9) ; le backend le sert : `RouteGeneratorGateway` (clé de cloisonnement, dépôt en flux avec `Expect: 100-continue`, erreurs RFC 9457), `RouteGeneratorService` (droits, quota, limite de débit et interrupteur du planificateur inchangés), contrôle géométrique de chaque proposition, D+ et D- demandés en `fast` (`GeneratedRouteAscent`, 2,5 s pour l'ensemble, `null` sinon), travail nocturne `RouteGeneratorOverlayJob` (02:10 UTC, verrou consultatif, une équipe à la fois, redépôt à 7 jours de l'expiration, surcouche d'une équipe supprimée effacée) et son déclencheur `POST /api/admin/route-generator/overlays/refresh`. Les trois erreurs nouvelles : hors région, réseau pas encore préparé, moteur indisponible. Le site : curseur, part sur les routes de l'équipe, messages (`WEB-179`). Retiré : le paquet `service/route/generator`, le cache du réseau, leurs tests et réglages. Couvert par `RouteGeneratorResourceTest`, `RouteGeneratorOverlayJobTest`, `AdminRouteGeneratorResourceTest`, `RouteGeneratorGatewayHttpTest`, `GeneratedRouteAscentTest`, `GeneratedRouteSanityTest`, `RouteGeneratorErrorsTest`, `RouteGeneratorOverlayQueryCountTest`, `FakeRouteDetailsGatewayTest` (écrits, non lancés). **À ne pas défaire** : `network_edges` et son rattrapage restent (ils nourrissent le dépôt) ; la case « exclu du générateur » part avec chaque trace ; un document non actuel part en `null` ; les garanties sont vérifiées par le service, le backend ne refait que le contrôle géométrique ; une pause des appels `fast` ne vient jamais d'une interruption de notre côté ; la clé ne s'écrit jamais dans un journal ni dans un message d'erreur.
