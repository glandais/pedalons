## Livré

`API-179` **Dupliquer un parcours** (2026-11-12, **contrat `14.1.0`**, mineure, ajout pur ; aucune migration) — `POST /api/teams/{teamSlug}/routes/{routeSlug}/duplicate`, corps `RouteDuplicateRequest { name }` (mêmes règles que `RouteRequest.name`) → `201 RouteDto`, réservé à qui peut modifier la source (`@CheckAccess(ROUTE, UPDATE)` : organisateur, parcours activés ; administration de la plateforme). `RouteCopyService.duplicate` **rejoue la création** : il lit la source dans une transaction courte (GPX d'origine `ROUTE_ORIGINAL_GPX`, état du planificateur par `RouteService.readPlannerState`, revêtements, points du parcours en brouillons, tags), télécharge le GPX hors transaction, puis appelle `RouteService.createRoute` à six arguments avec le nouveau nom, la visibilité, le type de revêtement, les tags et des médias **copiés** : slug, statistiques, vignettes, GPX/FIT et rattrapage d'altitude sont recalculés ; commentaires, sorties et statistiques restent sur l'original. `AssetService.copyMedia` (`MANDATORY`) recopie logo, images citées et pièces jointes sous de nouveaux `fileId`, réécrit les `::asset{id=…}` du markdown (`rewriteAssetIds`), et supprime les fichiers S3 copiés si la transaction est annulée (`deleteUnlessCommitted`). Une source supprimée (y compris par la modération) répond 404, même à l'administration de l'équipe ; une source sans GPX d'origine, `GPX_EMPTY`. Tests qui couvrent : `RouteDuplicateResourceTest`. **À ne pas défaire** : le nom est le seul paramètre, tout le reste vient de l'original ; les médias sont copiés physiquement, jamais partagés entre deux contenus (`ASSET_NOT_AVAILABLE`, `AssetRemoveListener`) ; la copie passe par `createRoute`, jamais par une recopie de lignes.
