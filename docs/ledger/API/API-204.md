## Livré

`API-204` **Restaurer une page d'équipe vérifie le plafond de 3** (17 novembre 2026, contrat `15.0.1`
: la réponse 400 est désormais documentée sur `POST …/pages/{pageSlug}/undelete`) —
`TeamPageService.undeletePage` applique le contrôle de `createPage` : une page de la corbeille ne se
restaure pas quand l'équipe a déjà trois pages actives (`TOO_MANY_TEAM_PAGES`, 400). Restaurer une page
qui n'est pas supprimée ne déclenche pas le contrôle. Couvert par
`TeamPageServiceTest.UndeletePage.shouldThrowWhenRestoringPastMaxPages` et
`TeamPageResourceTest.undeletePage_atMax_shouldReturn400`. Le web (`WEB-185`) et l'app (`MOB-169`)
désactivent déjà « Restaurer » au plafond ; le serveur reste le garde-fou. Comme pour la création, le
comptage et l'écriture ne sont pas atomiques (deux restaurations simultanées peuvent passer) : accepté
pour un geste d'administration rare.
