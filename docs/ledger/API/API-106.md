## Livré

`API-106` **Plus de faux tunnels hors des zones LiDAR** (2026-10-14, contrat inchangé ; vcyclist 6.8.0) — la détection des tunnels de vcyclist tournait sur toute la trace, alors que sa précision n'est mesurée que sur un terrain issu du LiDAR : hors de France, Mapterhorn est souvent le GLO-30 (30 m, un modèle de surface), et une sonde dans les gorges du Dadès (Maroc) y avait trouvé trois faux tunnels — un faux tunnel aplatit une vraie montée. Depuis la 6.8.0, demandée pour l'occasion, le défaut de vcyclist est `TunnelScope.MEASURED_TERRAIN` : un tunnel n'est aplati que si son terrain vient d'une source mesurée (IGN LiDAR HD, ou Mapterhorn en France) ; ailleurs, il reste tel que lu, compté par `getTunnelsOutOfScope()` et signalé par un warning `tunnels: N tunnel-shaped bump(s) left as read at km …`, journalisé par `GpxPipeline.logCorrections`. Le backend garde `EngineModelJvm.elevationCorrectionOptions()` sans argument, donc ce défaut ; le choix se fait point par point, ce qui couvre aussi les traces frontalières, que le repli envisagé côté backend (`tunnels = false` pour une trace sans point en France) laissait de côté. Depuis la 6.7.0, un pont n'est de même détecté que sur un terrain IGN. Le test est côté vcyclist. **À ne pas défaire** : ne pas passer `TunnelScope.EVERYWHERE` sans une mesure de précision sur le terrain concerné.
