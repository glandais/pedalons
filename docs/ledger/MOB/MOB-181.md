## Reste à faire

`MOB-181` **Passer à maplibre 0.4 (moteur natif unique) (M)** — le code est migré (voir « Livré »),
mais rien n'a encore tourné sur un appareil : ni build iOS ou Android, ni Patrol. 0.4 remplace les SDK
MapLibre Android et iOS par un seul moteur (`maplibre_native`, l'API C de MapLibre Native, par FFI) :
tout ce qui suit est à **voir de ses yeux**, sur le simulateur iOS et sur le téléphone Android.

- **Les builds** : `flutter build ios --simulator` et `flutter build apk` (la bibliothèque C est
  récupérée par un *build hook* de `maplibre_native_ffi` ; iOS en Swift Package Manager, déjà le cas).
- **La couche de masse sous Android** (écran Parcours) : elle est désormais posée par `tiles`, sans le
  TileJSON écrit dans le cache que `MOB-55` avait ajouté pour `maplibre_android`.
- **Le cadrage initial** (`PdlMap._fit`, sortie, étape, fiche parcours, annonce) : les gardes contre la
  vue native sans taille (région visible réduite à un point sur iOS, `idle` jamais émis sur Android)
  sont gardées telles quelles ; elles sont peut-être devenues inutiles, à ne retirer qu'après l'avoir vu.
- **Le toucher** : tracé sélectionné, point de parcours, masse. `queryRenderedFeatures` est asynchrone,
  le toucher arrive donc une image plus tard.
- **La taille des images** (chevrons, pictogrammes et noms des points) : 0.4 pose une image à un pixel
  par point logique (`pixelRatio: 1`), ce que faisaient déjà les deux greffons 0.3 ; `icon-size` 1/3
  inchangé.
- **L'ombrage du relief** et le changement de fond de carte (la couche repose tout sur
  `onStyleLoaded`).
- **La suite Patrol iOS**, pour `MOB-174` (`ad_location_map_test`).

## Livré

Le 23 novembre 2026, `maplibre` passe de 0.3.7 à 0.4.0, en suivant le guide
« Upgrade from 0.3.x » et le skill `maplibre-migrate` du dépôt `flutter-maplibre` :

- Couches de style typées (`Expression`) à la place des cartes `paint`/`layout` : tracés, masse,
  réticule, départ/arrivée, halo, relief ; les mises en page `symbol` des chevrons et des points de
  parcours deviennent des fabriques (`pdlRouteArrowLayer`, `pdlWaypointIconLayer`,
  `pdlWaypointLabelLayer`) qui produisent le même JSON de style. `hillshade-*-color` reste une couleur
  seule, pas une liste.
- `style.layers` / `style.sources` remplacent `addLayer`/`removeSource`/`updateGeoJsonSource` ; le tracé
  sélectionné repasse au premier plan par `style.layers.move` (sous les chevrons) au lieu d'un
  retrait-ajout.
- `PdlMap` : `MapOptions(style: MapStyle.url, initCamera: CameraUpdate.position, movements)` ; changer
  de fond passe par `MapOptions.style` (plus de `setStyle`) ; un rappel par événement au lieu d'`onEvent`.
  Le paramètre `gestures` devient `movements` (`MapMovements`).
- `trackIdAt`, `massFeatureAt` et `waypointKeyAt` deviennent asynchrones (`queryRenderedFeatures`) ;
  `PdlMapBox` se convertit en `GeoBox` ; `MapCamera` → `CameraPosition` ;
  `revealWaypoint` anime en `CameraAnimation.fly`, comme les SDK de 0.3 (0.4 glisse par défaut).
- `PdlMassTiles.platformSource` et `tileJson` (le détour Android de `MOB-55`) sont retirés.
- Tests : `test/core/pdl/map/` tourne désormais sur les vraies collections `StyleLayers` /
  `StyleSources` de `maplibre` au-dessus d'un faux `StyleBackend` (d'où `maplibre_platform_interface`
  en dépendance de dev).
